# Design: Data Baseline

## Technical Approach

A stdlib-only Python package (`fundo/`). It generates deterministic Plaid-format data with generator-owned ground truth. A frozen keyword engine labels the same transactions. Label-agnostic feature and offer functions run on both label sets, and a report compares them. There is no LLM in this change, so no model/code boundary or cache applies yet. The features, offer and revenue rule are the deterministic code that the next change keeps.

## Module Layout

| File | Responsibility |
|---|---|
| `pyproject.toml` | flat layout (no install needed to run), `[tool.pytest.ini_options] pythonpath=["."]`, pytest as optional dev dep |
| `fundo/schema.py` | `GROUPS` (13 + `none`), `Transaction`/`Label`/`Business` TypedDicts, `is_revenue`, `risk_signal_for`, sign convention docstring |
| `fundo/casa_norte.py` | Hand-written biz_01 trap lines (data only) |
| `fundo/generate.py` | `Archetype`/`LineSpec` templates for biz_02–10, seeded generation, file writing |
| `fundo/legacy.py` | `RULES` list and `classify(txn) -> Label` |
| `fundo/features.py` | `compute_features(txns, labels, business) -> dict` |
| `fundo/offer.py` | `compute_offer(features) -> float` |
| `fundo/report.py` | Builds and prints the legacy-vs-truth report |
| `fundo/cli.py`, `__main__.py` | argparse: `all` / `generate` / `report`, `--seed 42`, `--out data/` |
| `tests/` | See Testing Strategy |

## Data Model and Files

- `data/transactions.json`: list with the PDF minimum fields plus `pending`, `transaction_type`, and `personal_finance_category {primary, detailed}`. The category is a noisy auxiliary field that the engine never reads. **Sign: credit > 0, debit < 0 (PDF convention, the reverse of native Plaid).**
- `data/businesses.json`: `{business_id, name, type, account_id, history_days, bank_charges_nsf_fee}`.
- `data/ground_truth.json` and `data/legacy_labels.json` have the same shape: `{transaction_id: {group, business, revenue, risk_signal, notes}}`.
- Group ids are snake_case (`nsf`, `overdraft`, `internal_transfer`, `ucc`, `active_advance`, `auto_deposit`, `revenue_verification`, `not_average_monthly_revenue`, `high_risk_{gambling,bankruptcy,debt_settlement,garnishment,other}`, plus `none`).
- `revenue = is_revenue(txn, group, business)`, which is true when amount > 0 AND business AND group == `none`.
- `risk_signal = risk_signal_for(group)`. Both are shared by truth and legacy, so neither is ever hand-labeled.

## Determinism

- Each business gets its own local `random.Random(business_seed(seed, business_id))`, where `business_seed` is the first 8 bytes of sha256(`"{seed}:{business_id}"`). Never the global RNG and never `hash()`. Editing one archetype therefore never changes another business's rows.
- Fixed `END_DATE = 2026-06-30`; `start = END_DATE - history_days + 1`.
- Amounts are integer cents internally and emitted as `round(cents/100, 2)`.
- Rows are sorted by `(business_id, date, description, amount)`, then ids are assigned by counter (`txn_biz_01_0001`).
- Archetypes are processed in fixed list order.
- `json.dumps(sort_keys=True, indent=2)` with a trailing newline.
- Money features are rounded to 2 decimals and ratios to 4.

## Data Flow

    casa_norte + archetypes --seed--> generate --> transactions, businesses, ground_truth
    transactions --> legacy.classify --> legacy_labels
    (txns, labels, business) --> features --> offer   [run twice: truth, legacy]
    truth vs legacy --> report --> stdout table + baseline_report.json

## biz_01 vs Templates

biz_01 is a hand-written list of about 18 trap lines with fixed dates, amounts and truth labels. A restaurant routine background is generated by the same template engine over 90 days. Without that background, avg monthly revenue would be meaningless.

biz_02–10 are `Archetype(meta, routine: [LineSpec], traps: [LineSpec])`. Each `LineSpec` has `(description variants, cents range, daily rate or fixed count, channel, merchant, truth group, business)`.

Routine vocabulary is shared and correctly handled by the engine. Errors therefore come only from the traps.

## Legacy Engine (frozen before traps are tuned)

The engine is an ordered list of `(keyword, group)` pairs. It does a case-insensitive substring match on `description`, with no normalization. The first match wins, and unmatched descriptions get `none`. `business` is always true. `revenue` and `risk_signal` come from the shared functions.

| Order | Keywords | Group |
|---|---|---|
| 1 | `nsf` | nsf |
| 2 | `overdraft` | overdraft |
| 3 | `ucc lien` | ucc |
| 4 | `square capital`, `ondeck`, `mca pmt`, `advance pmt` | active_advance |
| 5 | `casino`, `lucky`, `poker` | high_risk_gambling |
| 6 | `bankruptcy`, `ch 13 trustee` | high_risk_bankruptcy |
| 7 | `debt settlement` | high_risk_debt_settlement |
| 8 | `garnishment` | high_risk_garnishment |

| 10 | `acct verify` | revenue_verification |
| 11 | `auto dep` | auto_deposit |
| 12 | `refund`, `reversal` | not_average_monthly_revenue |

## Trap Planting (generic weakness → data)

| Business | Planted lines | Weakness exploited |
|---|---|---|
| biz_01 | `ONLINE XFER FROM SAV` credit; `SQUARE-CAPITAL REPAY` daily debits; NSF fee ×1; `LUCKY STAR CASINO` debit (caught); `GARNISH & CO PRODUCE` (hard negative, correctly `none`); Zelle catering credit containing instruction-like text (truth = legacy) | Abbreviation, punctuation |
| biz_02 | `bank_charges_nsf_fee=false`; `ITEM PAID INTO OD` **debits** (truth `overdraft`) | Missing vocabulary. Debits keep revenue unchanged. |
| biz_03 | `history_days=61`; routine only | Control for averaging |
| biz_04 | `NORTHSTAR FUNDING DISB` credit; daily `NORTHSTAR MCA-PMT` debits | No funding-credit rule; punctuation |
| biz_05 | Owner `ZELLE FROM M LOPEZ PERSONAL` credits (truth business=false) | Business flag hard-coded to true |
| biz_06 (sports bar) | Real casino debits plus `LUCKY DRAGON CHINESE BUFFET` | Over-broad `lucky` |
| biz_07 (auto repair shop) | `DEBT-SETTLEMENT`, `WAGE GARNISH.ORDER` debits (some unpunctuated, caught) | Punctuation |
| biz_08 | Daily `STRIPE TRANSFER ST-xxxx` payout credits | Substring collision: `nsf` inside "transfer" (rule 13 unreachable) → false decline |
| biz_09 | 5 × `NSF RETURN ITEM FEE` + 1 × `N.S.F. RETURN ITEM FEE`; routine also includes 2 savings sweeps (not traps, added per routine data policy) | Punctuation at the threshold |
| biz_10 | Routine only | Clean control |

## Features, Offer, Report

Features and the offer depend only on `(txns, labels, business)` and never on the label source:

- revenue_share = revenue / total credits
- nsf_count
- overdraft_count
- high_risk_debit_share, dollar-weighted
- avg_monthly_revenue = revenue / (history_days / 30)
- daily_funder_payments = sum of active_advance debits / distinct days with such debits (0 if none)
- offer = 0 if nsf_count > 5, else max(0, 1.2·avg_monthly_revenue − 20·daily_funder_payments)

`baseline_report.json` has the shape `{businesses: {business_id: {n_txns, accuracy: {group, business, revenue}, features: {truth, legacy, delta}, offer: {truth, legacy, delta}, decision, mislabels: {planned, unplanned, planned_by_trap, unplanned_by_pattern}, planned_only, collateral_only, collateral_flips_decision, collateral_changes_outcome}}, hypotheses: [{business_id, prediction, status, observed}]}`, with keys sorted. Delta = legacy − truth. Stdout shows one row per business.

## Architecture Decisions

| Option | Tradeoff | Decision |
|---|---|---|
| stdlib (dataclasses/TypedDict, json, random) vs pydantic/pandas | Deps add setup weight for ~2k rows | **stdlib** |
| biz_01 fully hand-written vs fully generated vs hybrid | Hand-only lacks 90-day volume; generated-only hides traps | **Hybrid**: hand traps + templated background |
| Rules frozen before data vs co-tuned | Co-tuning overfits and makes the delta meaningless | **Frozen first**; traps target generic weaknesses |
| Shared `is_revenue` vs per-labeler revenue | Separate rules would drift | **Shared** |
| Group ids snake_case vs README display strings | Display strings contain em dashes and spaces | **snake_case**, display map in schema |
| Assign ids after sort vs during generation | Assigning after sort keeps ids stable under merge | **After sort** |

## Testing Strategy

| Layer | Test | Approach |
|---|---|---|
| Unit | `test_legacy.py` | One case per weakness on literal strings (punctuation miss, `lucky` false positive, `transfer` breadth, order precedence) |
| Unit | `test_features.py`, `test_offer.py` | Hand-computed inline fixtures: NSF 5 → offer > 0, NSF 6 → 0, floor at 0, history_days 61 |
| Unit | `test_schema.py` | Every truth label satisfies `revenue == is_revenue(...)`; required fields; groups valid |
| Integration | `test_determinism.py` | Two `generate` runs into `tmp_path` are byte-identical; committed `data/` equals a regeneration |
| Integration | `test_predictions.py` | Parametrized per business from the report. "higher/lower" means \|Δoffer\| > 1% of the truth offer in that direction (a chosen materiality threshold, not a challenge requirement). biz_03 and biz_10 mean exact equality of labels, features and offer. biz_09 means truth = 0 and legacy > 0. biz_02 means nsf 0/0, legacy overdraft 0 < truth, Δoffer = 0. biz_06/07 means sign of Δhigh_risk_share and Δoffer = 0. |
| Integration | `test_biz01.py` | biz_01 contains each PDF trap kind |
